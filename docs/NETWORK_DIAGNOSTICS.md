# 网络保护与主动诊断（v0.4.0）

根据用户提供的扫描器与网络指南，吸收可以验证的路径约束与诊断方法。它们帮助排查配置错误、意外直连、出口变化与流式中断；没有验证数据支持量化“降低多少封号概率”，也不构成 Anthropic 官方账号安全判定。

## 五项核心能力

| 项目 | 已有实现 / 本版增加 | 尚需的 Ubuntu 验收 |
|---|---|---|
| DNS 防旁路 | 私有 resolver 挂载；隐藏常见主机解析 socket；拒绝 TCP/UDP 53 与 853；阻断探测与正向 HTTPS 对照 | 内核与挂载实测、权威 DNS 检测和抓包 |
| IPv6 约束 | 仅在专用 namespace 内禁用，不修改主机全局 IPv6；主动检查 IPv6 直连阻断 | Ubuntu namespace 与 IPv6 实际连接测试 |
| 明确代理路径 | 专用窗口只有唯一 relay 出口；受控模式约束代理服务 UID 只能连接指定远端 IPv4:端口 | 内核策略与真实代理验收；远端供应商出口另行观察 |
| 断线阻断 | 默认丢弃、无公网默认路由、无回退直连路径；启动器验证策略后才放行 | 测试机中停代理 / relay 的故障注入与抓包；不能拿普通连通测试替代 |
| 长连接 / 流式通道验证 | 本版新增固定 HTTPS 目标的约 20 秒滴流样本，记录持续收包跨度与一次连接复用观测 | 实际 Ubuntu 代理通道；真实 Claude SSE / WebSocket、长期会话、掉线重连仍待验收 |

图形界面「诊断与日志 → 核心保护与验收进度」逐项展示，区分已实现、尚未检测与本次测试通过。初始状态不会显示实机验收成功。

## 主动观测出口

面板点击「观测出口（联网）」，或用普通桌面用户执行：

```bash
claude-protect egress
```

命令经原有 root helper 与最终普通用户 guard 进入已核对的隔离环境。向 `https://api.ipify.org?format=json` 发出两次独立 HTTPS 请求：

- 只连接固定 relay，不在本机解析检测服务域名，不读取账号、Cookie 或 API Key。
- 使用标准证书验证，不跟随重定向，不信任非公网 IP 或超长 / 无效响应。
- 分别记录代理隧道与目标 TLS 建立耗时、响应头等待时间、HTTP 状态与结果。
- 采样前后重新检查隔离；策略变化时丢弃结果，不回退宿主直连。
- 单次采样有 20 秒绝对期限，避免慢速响应无限拖延；仅用户点击或执行命令时联网。

`complete` 只表示两次请求均完成，不表示账号安全。两次地址相同不能保证长期稳定；两次不同也不能推断账号违规。

**固定代理入口不是固定最终出口。** ipify 看到的 IP 不保证是 Anthropic 看到的 IP；供应商可能按目标分流、负载均衡或轮换出口。

只有通过图形面板完成的完整观测会保存到：

```text
~/.local/share/claude-protect/diagnostics/egress-history.json
```

目录权限 0700，文件权限 0600，最多 30 条。文件包含完整出口 IP；默认界面隐藏 IPv4 尾段 / IPv6 后缀。按目标与代理策略摘要比较上次记录，避免把主动换代理算成同一配置的异常变化。策略摘要不含密码。

历史不会上传或由后台定期查询；可以在面板清除。CLI 单独执行不会写历史。损坏、符号链接、硬链接、公开可读的历史文件会被拒绝；历史保存失败不会伪造第一次检查成功。

## 长连接与流式样本

在面板点击「验证流式通道（约 20 秒）」，或：

```bash
claude-protect stream-check
```

固定连接 `httpbin.org:443`，先请求 `/bytes/1`，完整读取后，在同一客户端连接对象上请求：

```text
/drip?duration=20&numbytes=10&delay=0&code=200
```

观察原有 TLS socket 是否复用，并逐字节记录 10 个预期字节的到达时间。只有完整收到预期响应、首末字节跨度至少 12 秒、至少三个间隔达到 0.5 秒才记为本次滴流通过。完全缓冲后集中返回会标为 `inconclusive`，不误判为流式通过。

检测使用标准 TLS 验证和 55 秒整体期限；前后重新核对隔离。第三方检测服务超时、限流、故障或返回非预期内容时，只显示本次测试结果，不能据此判定 Claude 账号状态。服务主动关闭 keep-alive 时不会伪造复用成功。

这是一个有时间上限的**通用 HTTPS 传输样本**，不使用 Claude 账号、提示词或额度，不证明真实 Claude SSE / WebSocket、长时间空闲、数小时会话或断线重连已通过。

## 离线配置检查

面板点击「检查当前环境（离线）」，或：

```bash
claude-protect audit
```

检查当前进程环境中的代理格式、大小写变量冲突、SOCKS 入口、非回环 `NO_PROXY`、API 端点覆盖、API Key 是否存在，以及关闭 TLS 验证的设置。只返回固定诊断描述与必要的存在性标记，不输出原始代理 URL、主机名、用户名、密码、API Key 或旁路列表。

如实显示 locale 与时区缩写作为环境信息，不给中文语言、字体或时区加“封号分”，不修改它们。

**范围是命令 / 面板自身环境。** 启动器会重建应用环境；运行中的 Claude、项目与 VS Code 设置、浏览器环境可能不同，尚未被这项检查读取或验证。发现宿主环境变量不代表专用窗口已旁路或已切换计费。

## 报告与第三方交叉验证

「导出脱敏报告」仅导出白名单状态、检查时间、已验证 / 失败 / 未测试结果和掩码 IP，不导出原始日志、环境变量值、用户目录、代理认证、账号凭据。报告使用 0600 权限保存，拒绝符号链接、硬链接和共享权限文件。IP 前缀仍可能识别网络，脱敏不等于匿名。

报告始终将真实 Claude 流式会话、浏览器 WebRTC、权威 DNS 与抓包标为未测试；通用滴流通过不会替代这些项目。

面板提供两个受保护浏览器入口：

- Net.Coffee 的 IP / DNS / WebRTC 对照页面。
- 浏览器环境扫描器。

只在用户点击时打开，经过相同的启动器、profile 与密钥链检查，不嵌入第三方脚本，不读取其分数，也不把分数当作通过依据。第三方页面会收到访问 IP。mDNS / 局域网候选地址不应直接算公网泄露，未出现 WebRTC 候选也不自动证明安全。
