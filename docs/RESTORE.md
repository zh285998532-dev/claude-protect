# 网速影响与还原系统配置（v0.6.0）

## 平时上网会怎样

本项目把指定 VS Code 窗口、其子进程和专用 Chrome 放在独立网络 namespace，通过指定代理联网。普通应用仍使用主机原来的网络路径。

安装只新增本项目的网络接口 / 连接子网、namespace、服务、sudo 授权、启动入口与专用规则。受控模式的主机防火墙表只匹配专用代理服务 UID。不会把主机默认路由、系统代理、主机 DNS 或主机全局 IPv6 改成项目设置。

因此，受保护窗口的联网速度取决于代理节点、延迟和连接稳定性；隔离 / 代理进程与其他程序也共享 CPU、内存和带宽，不能承诺完全没有资源影响。当前没有 Ubuntu 网速基准测试，不能给出性能损耗百分比。

外部 Clash / Mihomo / sing-box 如果启用全局代理或 TUN，会独立影响主机流量；该设置需要在其自身界面调整。本项目不持有那些配置的修改权或安装前快照。

## 图形还原入口

「连接配置」顶部有「还原系统配置」，页面底部有移除 / 保留范围说明；「使用指南」也提供相同入口。

1. 停止本轮环境检测，等待当前检查 / 安装结束。
2. 关闭受保护 VS Code、Chrome 及其后台进程。
3. 点击「还原系统配置」，查看范围并确认。
4. 在弹出的系统终端输入 Ubuntu 管理员密码。
5. 查看终端的清理核对结果，按 Enter 关闭终端，回到面板刷新。

有受保护进程时，卸载器会在停止服务前拒绝操作；底层 teardown 也会核对 namespace 身份与活跃进程。不会强制关闭应用以丢失未保存的工作。

还原会移除本项目的系统集成，后续需要重新安装组件才能继续使用保护入口。它不会把正在使用的保护窗口临时放成直连模式。

## 移除与保留

| 移除 | 保留 |
|---|---|
| 专用 namespace、veth 接口与该 namespace 的规则 | 主机原有 DNS、默认路由、系统代理和全局 IPv6 设置 |
| 受控模式专用 UID 的上游规则 | UFW、Docker 等其他防火墙表 |
| 本项目 systemd 系统服务与密钥链过滤用户服务 | 用户项目、普通 VS Code 配置 |
| 专用 sudo 授权、系统启动入口和组件文件 | 专用 VS Code / Chrome profile、Claude 登录资料 |
| 受控代理账号凭据文件；仅删除本项目创建的服务账号 | 外部代理软件与其配置、本机出口历史和诊断报告 |

发行包目录、PySide6 虚拟环境和用户的面板快捷方式保留，便于重新配置。保留数据不表示网络保护仍然启用。

## 清理核对与失败

卸载器停止专用服务、调用现有 teardown 后，会用只读查询核对 namespace / 网络接口已移除、专用上游表已移除、适用的系统服务已停止且没有 MainPID。只检查项目表，不执行主机 `flush ruleset` 或重启全局网络。

发现残留、规则归属无法验证、服务仍运行或系统查询失败时，不宣称还原完成，并保留后续配置和归属记录供修复。操作不保证事务式回滚；失败时部分服务可能已停止，应以终端错误为准，再核对残留。

还原终端返回后，面板区分「配置仍存在」「配套配置已移除」「未完成 / 被取消」。界面不会只因为终端窗口打开或关闭就报告还原成功，网络清理的详细核对结果以终端输出为准。

v0.6 将卸载脚本保存到 root 管理的 `/usr/local/share/claude-protect/uninstall.py`，可由面板优先调用；旧版未保存该脚本时，使用解压发行包中的 `scripts/uninstall.py`。普通用户不会自行执行特权清理，管理员密码始终由系统终端读取。

也可从发行包目录手动执行：

```bash
sudo python3 scripts/uninstall.py
```

## 验收状态

本轮增加清理核对和 GUI 流程测试，不会在 macOS 开发机执行 Ubuntu 还原。真实 systemd / nftables 清理、活跃应用拒绝、保留数据与普通网络连通性仍需 Ubuntu 实机验收。
